# 응답 저장 설정 (Google 스프레드시트 + Apps Script)

설문 페이지가 보내는 응답을 스프레드시트에 쌓기 위한 설정입니다.

---

## 1. Apps Script 열기

응답을 받을 스프레드시트에서 **확장 프로그램 → Apps Script**.

새 프로젝트가 열리면 `Code.gs` 안의 내용을 모두 지우고, 이 폴더의
[`Code.gs`](./Code.gs)를 통째로 붙여넣은 뒤 저장합니다.

> 반드시 스프레드시트 메뉴에서 열어야 합니다. Apps Script 사이트에서 새로 만든
> 프로젝트는 스프레드시트에 연결돼 있지 않아 `SpreadsheetApp.getActiveSpreadsheet()`가
> 아무것도 찾지 못합니다.

## 2. 배포

**배포 → 새 배포 → 유형 선택(톱니바퀴) → 웹 앱**

| 항목 | 값 |
|---|---|
| 설명 | 아무거나 (예: `v1`) |
| 실행 사용자 | **나** |
| 액세스 권한이 있는 사용자 | **모든 사용자** |

액세스를 "모든 사용자"로 두지 않으면 학생들이 제출할 때 로그인 화면으로 튕깁니다.
Google 계정 로그인을 요구하면 익명 조사가 아니게 되므로, 반드시 "모든 사용자"여야 합니다.

처음 배포할 때 권한 승인 창이 뜹니다. "고급 → 안전하지 않은 페이지로 이동"을 거쳐
승인하면 됩니다. 본인이 만든 스크립트라 나오는 경고입니다.

배포가 끝나면 **웹 앱 URL**을 복사합니다. `.../exec`로 끝나야 합니다.
(`.../dev`는 본인만 접근 가능한 테스트용이라 설문에 쓰면 안 됩니다.)

## 3. 페이지에 URL 연결

`index.html` 위쪽 설정 블록의 `ENDPOINT`에 붙여넣습니다.

```js
const ENDPOINT = "https://script.google.com/macros/s/AKfy.../exec";
```

## 4. 확인

1. 복사한 `/exec` URL을 브라우저 주소창에 그대로 붙여넣습니다.
   `{"ok":true,"alive":true,"sheet":"응답","rows":0}` 이 보이면 배포가 정상입니다.
2. Apps Script 편집기에서 `testInsert` 함수를 골라 실행합니다.
   `응답` 시트에 한 줄이 생기면 저장 경로가 정상입니다. 확인 후 그 줄은 지웁니다.
3. 설문 페이지를 끝까지 채워 제출해보고 시트에 쌓이는지 봅니다.

---

## 코드를 고쳤을 때

**저장만 하면 반영되지 않습니다.** 배포된 웹앱은 배포 시점의 코드를 계속 씁니다.

**배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포**

이렇게 하면 URL은 그대로 유지되면서 코드만 갱신됩니다. "새 배포"를 다시 만들면
URL이 바뀌어 `index.html`도 같이 고쳐야 하니 주의하세요.

## 시트 열 이름

| 열 | 내용 |
|---|---|
| `id` | 제출 식별자 (중복 제거용, 아래 참고) |
| `ts` | 응답자 브라우저 기준 제출 시각 (ISO) |
| `weeklyMin` | 결과 화면에 표시된 주간 추정 시간 (분) |
| `ref` | 유입 경로. `?ref=인스타` 처럼 붙이면 여기 기록됩니다 |
| `f0` ~ `f8` | 1단계 빈도 문항 01~09 (순서대로) |
| `q10` ~ `q27` | 문항 번호 그대로. `q17b`는 17-1번 |
| `ocir_participated` | OCI-R-K 선택 섹션 참여 여부. 1 = 참여, 0 = 건너뜀 |
| `ocir_1` ~ `ocir_18` | OCI-R-K 문항별 원점수 0~4 |
| `ocir_total` | OCI-R-K 총점 0~72 |
| `ocir_hoarding` 외 5개 | 하위척도 점수 0~12 (checking, ordering, neutralizing, washing, obsessing) |

새 문항을 추가하면 열이 **오른쪽에 자동으로 늘어납니다.** 기존 행은 그 열이 빈 채로
남습니다. OCI-R-K 열들도 이 방식으로 붙었으므로 스크립트는 손대지 않았습니다.

OCI-R-K 열의 해석과 주의사항은 [`docs/OCI-R-K.md`](../docs/OCI-R-K.md)를 보세요.
특히 규준 표본의 한계와 18번 문항의 성차는 분석 전에 반드시 읽어야 합니다.

## 실패했을 때 어디를 보나

지금 페이지는 `mode:'no-cors'`로 전송합니다. 브라우저가 응답 내용을 읽지 못하는
방식이라, **서버에서 오류가 나도 응답자 화면에는 "제출 완료"가 뜹니다.**

그래서 스크립트가 실패를 `_오류` 시트에 남기도록 해뒀습니다. 응답 수가 예상보다
적다 싶으면 이 시트를 먼저 확인하세요. 시각, 오류 내용, 받은 본문이 들어 있어
대부분 손으로 복구할 수 있습니다.

`_오류` 시트는 첫 실패가 났을 때 자동으로 생깁니다. 시트가 없다면 아직 실패한
적이 없다는 뜻입니다.

### 자주 나오는 오류

**`범위의 좌표 또는 크기가 잘못되었습니다` / 응답이 한 건도 안 쌓임**

새로 만든 시트는 기본 **26열**이고, 시트는 필요하다고 열을 알아서 늘려주지
않습니다. 이 설문은 OCI-R-K 를 포함하면 **58열**이라 반드시 넘습니다.

지금 코드에는 모자란 만큼 열을 먼저 늘리는 처리가 들어 있습니다. 이 오류가
난다면 **예전 코드가 배포된 상태**입니다. 최신 `Code.gs` 를 붙여넣고 아래
'코드를 고쳤을 때' 대로 새 버전을 배포하세요.

**`실행 기록`에 아무것도 없음**

요청이 스크립트까지 오지 못한 것입니다. 페이지의 `ENDPOINT` 가 비어 있거나
옛날 파일이거나, 배포의 액세스 권한이 "모든 사용자"가 아닌 경우입니다.
`/exec` URL 을 브라우저에 직접 붙여넣어 확인하세요.

## 아직 남은 것

- **중복 제거가 아직 켜지지 않았습니다.** 스크립트는 `id`가 같은 응답이 두 번
  들어오면 두 번째를 버리도록 돼 있지만, 지금 페이지는 `id`를 보내지 않습니다.
  페이지 쪽에 한 줄 추가하면 활성화됩니다.
- **제출 실패를 응답자가 알 수 없습니다.** 위에 적은 `no-cors` 문제입니다.
  일반 CORS 방식으로 바꾸면 실패를 감지해 재시도할 수 있습니다.
- **새로고침하면 응답이 날아갑니다.** 중간에 실수로 새로고침한 응답자는
  처음부터 다시 해야 합니다.

## 개인정보

- 이 스크립트는 이름·학번·연락처를 받지 않습니다. IP도 기록하지 않습니다
  (Apps Script는 애초에 요청 IP를 제공하지 않습니다).
- 인터뷰 신청은 **반드시 별도 폼으로 분리**하세요. 같은 시트에 연락처가 들어가면
  응답과 연결되어 익명성이 깨집니다. `index.html`의 `INTERVIEW_URL`에 다른 폼
  주소를 넣는 구조가 그 때문입니다.
- 스프레드시트 공유 범위를 확인하세요. 링크가 있는 사람 모두 열람 가능으로 두면
  응답 전체가 공개됩니다.
